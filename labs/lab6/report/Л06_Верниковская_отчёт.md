# Цель работы

Целью данной работы является развитие навыков администрирования ОС Linux. Плучение первого практического знакомства с технологией SELinux. Проверка работы SELinx на практике совместно с веб-сервером Apache.

# Выполнение лабораторной работы

Зайдём в систему с полученными учётными данными и убедимся, что SELinux работает в режиме enforcing политики targeted с помощью команд *getenforce* и *sestatus* (рис. [-@fig:001])

![Проверка режима работы SELinux](image/лаба6_1.png){#fig:001 width=70%}

Установим httpd.service с помощью *sudo yum install httpd* (рис. [-@fig:002])

![Установка httpd](image/лаба6_2.png){#fig:002 width=70%}

Далее запустим веб-сервер и посмотрим его статус, чтобы убетиться что он работает. Сделаем это с помощью команд *sudo systemctl start httpd* и *service httpd status* (рис. [-@fig:003])

![Проверка работы Apache](image/лаба6_3.png){#fig:003 width=70%}

Найдём веб-сервер Apache в списке процессов командой *ps auxZ | grep httpd* и определим его контекст безопасности. Его контекст безопасности httpd_d (рис. [-@fig:004])

![Контекст безопасности Apache](image/лаба6_4.png){#fig:004 width=70%}

Посмотрим текущее состояние переключателей SELinux для Apache с помощью команды *sestatus -b httpd* (рис. [-@fig:005])

![Состояние переключателей SELinux](image/лаба6_5.png){#fig:005 width=70%}

Посмотрим статистику по политике с помощью команды *seinfo*. Множество пользователей - 8, ролей - 40, типов - 5169 (рис. [-@fig:006])

![Статистика по политике](image/лаба6_6.png){#fig:006 width=70%}

Определим тип файлов и поддиректорий, находящихся в директории /var/www, с помощью команды *ls -lZ /var/www*. Владелец - root, права на изменения только у владельца. Файлов в директории нет, есть только поддиректории (рис. [-@fig:007])

![Типы поддиректорий в директории /var/www](image/лаба6_7.png){#fig:007 width=70%}

Определим тип файлов, находящихся в директории /var/www/html: *ls -lZ /var/www/html*. Там нет файлов. Создать из может только суперпользователь (рис. [-@fig:008])

![Типы файлов в директории /var/www/html](image/лаба6_8.png){#fig:008 width=70%}

Создадим от от имени суперпользователя html-файл /var/www/html/test.html (рис. [-@fig:009]), (рис. [-@fig:010]), (рис. [-@fig:011])

![Создание файла test.html](image/лаба6_9.png){#fig:009 width=70%}

![Открытие файла test.html](image/лаба6_10.png){#fig:010 width=70%}

Листинг программы test.html:

```
<html>
<body>test</body>
</html>
```

![Файл test.html](image/лаба6_11.png){#fig:011 width=70%}

Проверим содержание файла с помощью команды cat (рис. [-@fig:012])

![Содержание файла test.html](image/лаба6_12.png){#fig:012 width=70%}

Проверим контекст созданного нами файла командой *ls -lZ*. По умолчанию это httpd_sys_content_t (рис. [-@fig:013])

![Контекст файла test.html (1)](image/лаба6_13.png){#fig:013 width=70%}

Обратимся к файлу через веб-сервер, введя в браузере адрес http://127.0.0.1/test.html. Файл успешно отображён (рис. [-@fig:014])

![Отображение файла test.html](image/лаба6_14.png){#fig:014 width=70%}

Изучим справку *man httpd*. Для httpd определён контекст файла httpd_sys_content_t(рис. [-@fig:015])

![Справка по команде httpd](image/лаба6_15.png){#fig:015 width=70%}

Опять проверим контекст файла (рис. [-@fig:016])

![Контекст файла test.html (2)](image/лаба6_16.png){#fig:016 width=70%}

Изменим контекст файла /var/www/html/test.html с httpd_sys_content_t на любой другой, к которому процесс httpd не должен иметь доступа, например, на samba_share_t: *chcon -t samba_share_t /var/www/html/test.html*. И проверим командй *ls -Z /var/www/html/test.html* что контекст был изменён (рис. [-@fig:017])

![Изменение контекста файла test.html](image/лаба6_17.png){#fig:017 width=70%}

Попробуем ещё раз получить доступ к файлу через веб-сервер, введя в браузере адрес http://127.0.0.1/test.html. Мы получили сообщение об ошибке. Это произошло потому что установлен контекст, к которому процесс httpd не имеет доступа (рис. [-@fig:018])

![Ошибка отображения файла test.html](image/лаба6_18.png){#fig:018 width=70%}

Просмотрим системный лог-файл: *tail /var/log/messages*. Те же ошибки мы можем увидеть в файле /var/log/audit/audit.log (рис. [-@fig:019]), (рис. [-@fig:020])

![Просмотр файла /var/log/messages](image/лаба6_19.png){#fig:019 width=70%}

![/var/log/audit/audit.log](image/лаба6_20.png){#fig:020 width=70%}

Далее попробуем запустить веб-сервер Apache на прослушивание ТСР-порта 81 (а не 80, как рекомендует IANA и прописано в /etc/services). Для этого в файле /etc/httpd/conf/httpd.conf найдём строчку Listen 80 и заменим её на Listen 81 (рис. [-@fig:021]), (рис. [-@fig:022])

![Открытие файла /etc/httpd/conf/httpd.conf (1)](image/лаба6_21.png){#fig:021 width=70%}

![Редактирование файла /etc/httpd/conf/httpd.conf (1)](image/лаба6_22.png){#fig:022 width=70%}

Выполним перезапуск веб-сервера Apache. Произошёл сбой, так как порт 80 для локальной сети, а 81 нет (рис. [-@fig:023])

![Попытка прослушивания другого порта](image/лаба6_23.png){#fig:023 width=70%}

Далее проанализируем лог-файлы *tail -nl /var/log/messages* (рис. [-@fig:024])

![Проверка лог-файлов](image/лаба6_24.png){#fig:024 width=70%}

Посмотрим файлы /var/log/httpd/error_log, /var/log/httpd/access_log и /var/log/audit/audit.log (рис. [-@fig:025]), (рис. [-@fig:026]), (рис. [-@fig:027])

![Файл /var/log/httpd/error_log](image/лаба6_25.png){#fig:025 width=70%}

![Файл /var/log/httpd/access_log](image/лаба6_26.png){#fig:026 width=70%}

![Файл /var/log/audit/audit.log](image/лаба6_27.png){#fig:027 width=70%}

Выполним команду *semanage port -a -t http_port_t -p tcp 81*. И после этого проверим список портов командой *semanage port -l | grep http_port_t*. Порт 81 появился в списке (рис. [-@fig:028]), (рис. [-@fig:029])

![Добавление порта 81](image/лаба6_28.png){#fig:028 width=70%}

![Проверка списка портов (1)](image/лаба6_29.png){#fig:029 width=70%}

Перезапустим сервер Apache. Теперь он работает, так как мы внесли порт 81 в список портов httpd_port_t (рис. [-@fig:030])

![Перезапуск сервера](image/лаба6_30.png){#fig:030 width=70%}

Вернём контекст httpd_sys_cоntent__t к файлу /var/www/html/test.html: *chcon -t httpd_sys_content_t /var/www/html/test.html*. После этого попробуем получить доступ к файлу через веб-сервер, введя в браузере адрес http://127.0.0.1:81/test.html (рис. [-@fig:031])

![Отображение файла test.html (порт 81)](image/лаба6_31.png){#fig:031 width=70%}

Исправим обратно конфигурационный файл apache, вернув Listen 80 (рис. [-@fig:032]), (рис. [-@fig:033])

![Открытие файла /etc/httpd/conf/httpd.conf (2)](image/лаба6_32.png){#fig:032 width=70%}

![Редактирование файла /etc/httpd/conf/httpd.conf (2)](image/лаба6_33.png){#fig:033 width=70%}

Удалим привязку http_port_t к 81 порту: *semanage port -d -t http_port_t -p tcp 81* и проверим, что порт 81 удалён  (рис. [-@fig:034]), (рис. [-@fig:035])

![Удаление привязки http_port_t к 81 порту](image/лаба6_34.png){#fig:034 width=70%}

![Проверка списка портов (2)](image/лаба6_35.png){#fig:035 width=70%}

Удалим файл /var/www/html/test.html: *rm /var/www/html/test.html* (рис. [-@fig:036])

![Удаление файла test.html](image/лаба6_36.png){#fig:036 width=70%}
